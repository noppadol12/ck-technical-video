# เฟส 5 — แผนผังวงจร (CK Wiring)

วาดแผนผังวงจรในหลังบ้าน แล้วเผยแพร่ให้ลูกค้าเห็นในเว็บวิดีโอ แทนไฟล์ PDF บน Google Drive

- โปรแกรมวาด: `https://video.ckaircond.com/admin/wiring/` (ใช้ล็อกอินแอดมินเดิม หรือกดเมนู **วาดแผนผังวงจร** ในหลังบ้าน)
- ลูกค้า: เห็นแผนผังในหมวดที่เลือก ปนกับแผนผัง PDF เดิม (ตัวกรอง "แผนผังวงจร") เปิดแล้วซูม/เลื่อน/ดาวน์โหลด PNG ได้ ใช้งานบนมือถือได้

## ติดตั้ง (ครั้งเดียว)

**1. ฐานข้อมูล** — Supabase → **SQL Editor** → วางไฟล์ `supabase/phase5.sql` → **Run**

เพิ่มเฉพาะของใหม่ ไม่แก้ข้อมูลเดิม รันซ้ำได้:

| ของใหม่ | ใช้ทำอะไร |
| --- | --- |
| ตาราง `diagrams` | แผนผัง (ฉบับที่กำลังแก้ + ฉบับที่ลูกค้าเห็น) |
| ตาราง `wiring_assets` | รูปในแผนผัง (รูปสินค้า โลโก้ รูปที่แคป) |
| ตาราง `wiring_settings` | คลังอุปกรณ์ และค่าเริ่มต้นกรอบชื่อบริษัท |
| คอลัมน์ `watch_logs.diagram_id` | บันทึกการเปิดดูแผนผัง (เห็นในรายงานการดู ชื่อขึ้นต้นด้วย "แผนผัง:") |

**2. Deploy** — merge Pull Request เข้า `main` → Cloudflare Pages deploy ให้เอง ไม่ต้องตั้ง key เพิ่ม

> โค้ดชุดนี้ทนต่อการ deploy ก่อนรัน SQL: หน้าลูกค้าแสดงวิดีโอและ PDF ตามปกติ มีแค่โปรแกรมวาดที่จะแจ้งให้รัน `phase5.sql` ก่อน

## ทดสอบบน Preview ก่อน merge (ไม่บังคับ)

ทุก branch ที่ push ขึ้น GitHub จะได้ลิงก์ preview ของ Cloudflare (ดูในแท็บ **Deployments** ของโปรเจกต์) โดยไม่กระทบเว็บจริง

- ถ้า preview ล็อกอินไม่ได้: **Settings → Variables and Secrets** ใส่ key 3 ตัวเดียวกับ Production ให้ environment **Preview** ด้วย
- preview ใช้ฐานข้อมูลเดียวกับเว็บจริง: ทดสอบเผยแพร่ได้ แต่ **อย่าเลือก "ใช้แทนไฟล์ PDF เดิม"** ตอนทดสอบบน preview เพราะ PDF นั้นจะถูกซ่อนจากลูกค้าในเว็บจริงทันที ขณะที่เว็บจริง (ก่อน merge) ยังแสดงแผนผังใหม่ไม่ได้

## ใช้งาน

| ทำอะไร | วิธี |
| --- | --- |
| เริ่มงานใหม่ | ☰ งานทั้งหมด → งานใหม่ |
| ย้ายงานจากโปรแกรมในเครื่อง | ☰ งานทั้งหมด → นำเข้า → เลือกไฟล์ `.ckw.json` ได้หลายไฟล์พร้อมกัน (รวม `_คลังอุปกรณ์.ckw-lib.json` และไฟล์ "สำรองทั้งหมด") |
| บันทึก | อัตโนมัติขึ้นระบบทุกครั้งที่แก้ ถ้าเน็ตหลุดจะเก็บไว้ในเครื่องก่อน แล้วส่งขึ้นเองเมื่อออนไลน์ |
| ให้ลูกค้าเห็น | ปุ่ม **เผยแพร่** → เลือกหมวด → (ถ้ามี) เลือก PDF เดิมที่จะแทน → เผยแพร่ |
| แก้หลังเผยแพร่ | แก้ได้เลย ลูกค้ายังเห็นฉบับเดิมจนกว่าจะกด **อัปเดตให้ลูกค้า** (จุดสีส้มบนปุ่ม) |
| หยุดแสดง | เผยแพร่ → หยุดเผยแพร่ (PDF ที่เคยถูกแทนจะกลับมาแสดงเอง) |
| ส่งลิงก์ให้ลูกค้า | เผยแพร่ → คัดลอกลิงก์ลูกค้า (ลูกค้าต้องล็อกอินด้วยรหัสก่อน เหมือนวิดีโอ) |
| ลบงาน | ☰ งานทั้งหมด → ไอคอนถังขยะ (owner เท่านั้น) |

## ความปลอดภัย

- API หลังบ้าน `/api/admin/wiring/*` ผ่าน middleware แอดมินเดิม ทุกการสร้าง/เผยแพร่/ลบถูกบันทึกใน `admin_actions`
- ลูกค้าเห็นเฉพาะฉบับที่กดเผยแพร่ (`diagrams.published`) ฉบับร่างดึงไม่ได้
- รูปใช้ id เป็น sha256 ของไฟล์ (เดาไม่ได้) และต้องล็อกอินก่อนเปิด
- บันทึกพร้อมกันจาก 2 หน้าต่าง: ระบบเช็กเลข `revision` ไม่ให้บันทึกทับกัน หน้าต่างที่ช้ากว่าจะขึ้นแจ้งให้โหลดฉบับล่าสุด

## API ที่เพิ่ม

| Endpoint | หน้าที่ |
| --- | --- |
| `GET/POST /api/admin/wiring` | รายการแผนผัง / สร้างใหม่ |
| `GET/PUT/DELETE /api/admin/wiring/:id` | เปิด / บันทึก (ต้องส่ง `revision`) / ลบ (owner) |
| `POST /api/admin/wiring/:id/publish` | `{ publish, category_id, replace_video_id }` เผยแพร่ / อัปเดต / หยุด |
| `POST /api/admin/wiring/assets` · `GET …/assets/:id` | อัปโหลดรูป (ไฟล์ดิบ ≤ 500 KB) / เปิดรูป |
| `GET/PUT /api/admin/wiring/settings` | คลังอุปกรณ์ / ค่าเริ่มต้นกรอบชื่อบริษัท |
| `GET /api/diagrams/:id` | (ลูกค้า) แผนผังฉบับที่เผยแพร่ |
| `GET /api/wiring/assets/:id` | (ลูกค้า) รูปในแผนผัง |

`/api/videos` ส่งแผนผังที่เผยแพร่มาด้วย (`kind: 'pdf'`, `diagram: true`) และ `/api/videos/:id/play` เปิดหน้า `/wiring/view.html` ให้แผนผัง

ตัววาดแผนผังอยู่ที่ `public/wiring/render.js` ใช้ร่วมกันระหว่างโปรแกรมวาดและหน้าลูกค้า ภาพจึงตรงกันเสมอ
